# Implementation decisions

Single Next.js client dashboard with separate demo (localStorage) and hosted Supabase persistence. Supabase RLS is the authorization boundary; UI controls only improve usability. No privileged key in browser. Roles are provisioned by a trusted administrator, never self-selected outside demo.

Audit fixes (2026-11-06): managed demo schedules now project into the operational match state on load and after editing, preserving confirmed scores. Knockout winner references advance after a decisive confirmed score; an already played downstream match prevents changing its participants. Generated brackets explicitly name the final, while imported round names are preserved. Round-robin playing rounds share standings for medals, and third-place/semifinal labels cannot also match the final. Schedule edits check school/venue conflicts across competitions at the same start time; event duration is not currently modeled. The competition manager is available only in demo mode: hosted competition creation still requires reviewed Supabase setup, and the UI says so instead of writing browser-only data while in hosted mode.

Hosted athlete edits update the existing registration's name/bib without moving its school or competition; zero affected rows are treated as an error. Public legacy medals referencing a competition outside the current readable scope are omitted from that snapshot, without widening RLS. Hosted logos/short names remain browser-local but are reloaded when reopening the profile. School signup remains an explicitly labeled preview; enabling signup and hosted competition creation are separate deployment work, not implied by passing fixture tests.

School, school_admin, recorder and referee roles retain access to the account page so they can refresh their session, sign out or return to demo mode. This does not grant access to administrator or scoring controls beyond each role's existing permissions.

E2E starts a fresh production Webpack build/server with fixture-only Supabase URL/key, never reuses an existing development server, and intercepts hosted API calls. Run `PLAYWRIGHT_TEST_PORT=3100 npm run test:e2e` when port 3000 is already in use. No SQL migration is run by the test or build commands.

Verified on 2026-11-06: 56 unit/isolated SQL tests, 30 browser E2E tests, TypeScript, and the production Webpack build passed. Browser coverage includes hosted athlete editing without duplicate insertion, presentation fields after reopening, managed schedule reloads, knockout advancement/downstream protection, and the existing demo/registration/referee/mobile/PDF flows. This is fixture/PGlite validation, not a claim that the live Supabase deployment or its policies have been changed or verified.

Admins can seed the demo browser with ten schools, all registration-rule competitions, every round-robin pairing, scheduled dates/times and venues, and quota-valid athlete rosters from the account page. Demo fixtures are also projected into the dashboard's match state so the main schedule page, standings, and overview see the generated program; all matches remain scheduled with no scores. The sample program runs November 16–24, 2026, with nine 45-minute rounds per competition coordinated so schools and venues do not overlap; it merges with existing demo state and preserves previously edited fixture times/venues. All demo data stays in localStorage and is never written to Supabase.

The schedule page provides two diagrams for round-robin competitions: a per-round pairing bracket that links each school to its scheduled match, and a full matrix that shows the round for every school pairing. Date/venue match cards remain available alongside the diagrams, and rounds can be changed without drawing all fixtures over one another.

Competition scope is sport + division + gender + pool. Team events use manually selected pools and round robin, configurable schedules, integer final scores and 3/1/0 standings. Athletics supports timed heats, explicit advancement to finals, ties and non-finishing statuses. Medal totals are calculated from confirmed final match results, completed round-robin standings, and athletics final rankings; qualifying and semifinal results alone do not award medals. Browser-saved legacy medal entries remain visible separately and are not included in calculated totals. PDFs use browser print styles for Thai text.

Referee and recorder accounts have a work dashboard, read-only schedule, assigned-match result confirmation, and assigned athletics event result entry (including DNS/DNF/DQ and advancement from assigned heats). Admins assign team matches and athletics events by referee profile UUID. The additive `supabase/migrations/20261106_referee_workflow.sql` adds the match assignment field, restrictive RLS policies, and database guards that prevent schedule edits, unassigned result writes, or referee self-assignment. Apply and verify this migration on the normalized Supabase project before enabling referee accounts; it has not been run against the hosted project.

Validation: domain unit tests, TypeScript, production build, browser workflow and PDF generation. Live Supabase and authenticated RLS require an actual configured project and identities; SQL verification instructions are included. No deployment is configured before GitHub push.

## School portal

The school role keeps the existing dashboard navigation and adds separate “School profile” and “Athletes and coaches” menu items. The existing overview, athlete registration, schedule, standings, and medal pages remain available with school-specific summaries and read-only competition results. The added roster page asks the school to select a competition first, then enter athletes followed by coach/staff details and submit both together with one “Register” button; the school account is already bound to its school, so it does not show a school selector. Existing coach records remain editable below the athlete list. CSV import remains available as a separate athlete-only path. Athlete registration reuses the existing competition rules, quota checks, and Supabase RLS path. In demo mode, school profile details and coach records are saved to browser storage; hosted mode only edits the existing school name and registers athletes. Coach storage and additional school profile fields are intentionally not written to Supabase because the current schema has no corresponding fields/table or reviewed RLS policies.

School logos and abbreviated names are stored in browser storage in both demo and hosted mode, not in Supabase; they are therefore local to that browser. The abbreviated name is used in competition displays and falls back to the full school name when unset. Logo uploads are limited to PNG, JPG, or WEBP files up to 3 MB and are resized before browser storage.
