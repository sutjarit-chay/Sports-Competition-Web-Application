# เครื่องมือผู้ดูแลระบบ

เข้าสู่ระบบด้วยบัญชีผู้ดูแล แล้วเปิด **โรงเรียน / บัญชี** เครื่องมือทั้งหมดตรวจสิทธิ์ `profiles.role = admin` ที่เซิร์ฟเวอร์ ไม่รับ role ที่ผู้ใช้ส่งมา และไม่แก้ schema, constraint หรือ RLS

## โรงเรียน

- **จัดการโรงเรียน → แก้ชื่อ** เปลี่ยนชื่อโดยรักษา UUID และทะเบียนเดิม
- **ตรวจสอบการลบ** แสดงจำนวนบัญชี ทะเบียน ตาราง ผล เหรียญ ไฟล์ และสายแข่งขันที่เชื่อมโยง
- ลบได้เมื่อไม่มีข้อมูลเชื่อมโยงและพิมพ์ชื่อโรงเรียนตรงกับที่แสดง หากมีบัญชีโรงเรียน ให้ย้ายบัญชีไปโรงเรียนอื่นก่อน ส่วนข้อมูลแข่งขันต้องจัดการก่อนลบ
- ประวัติและโลโก้ของโรงเรียนที่ลบจะเก็บไว้ใน private Storage เพื่อกู้คืน ไม่แสดงในข้อมูลสาธารณะหลังลบโรงเรียน
- หากมีข้อมูลใหม่หลังตรวจตัวอย่าง ระบบปฏิเสธการลบและให้ตรวจใหม่ ไม่ลบบัญชี Auth หรือผลการแข่งขันตามโรงเรียนโดยอัตโนมัติ

## บัญชีโรงเรียนและกรรมการ

รายการแสดง username ชื่อผู้ใช้ สิทธิ์ และโรงเรียน เฉพาะบัญชีที่ได้รับอนุมัติ บัญชีที่ยังรอตรวจอยู่ในส่วนอนุมัติเดิม

- แก้ username ผ่าน server-managed `app_metadata.login_username` จึงไม่เปลี่ยนอีเมลภายใน UUID รหัสผ่าน หรือทะเบียนเดิม
- Username 3–32 ตัว ใช้ตัวอักษรอังกฤษพิมพ์เล็ก ตัวเลข จุด ขีดกลาง และขีดล่างตามกฎเดิม ชื่อที่เคยจองจะสงวนไว้ให้บัญชีเดิม ป้องกันการสวมชื่อและการแก้ชื่อพร้อมกัน
- ย้ายบัญชีโรงเรียนได้เฉพาะไปโรงเรียนที่มีอยู่ โดยไม่เปลี่ยนบทบาทและไม่ย้ายทะเบียนเก่าของโรงเรียนนั้น
- **ตั้งรหัสผ่านใหม่** รองรับ 10–128 ตัวอักษร มีปุ่มสร้างและแสดง/ซ่อนรหัสที่เพิ่งกรอก เมื่อบันทึกสำเร็จจะล้างช่องกรอก ให้จดหรือส่งรหัสใหม่ให้เจ้าของบัญชีก่อนปิด
- ไม่สามารถดูรหัสผ่านเดิมได้ รหัสผ่านไม่อยู่ในรายการบัญชี Auth metadata ไฟล์สำรอง หรือ log ของระบบ
- เครื่องมือส่วนนี้ไม่อนุญาตให้แก้บัญชี admin หรือยกระดับสิทธิ์

## เริ่มการแข่งขันใหม่

ขอบเขตที่ผู้ใช้เลือก: **ล้างนักกีฬา ผู้ฝึกสอน ตาราง ผล และเหรียญ โดยเก็บโรงเรียน บัญชีผู้ใช้ และกติกากีฬาไว้**

ข้อมูลที่ล้าง:

- `registrations` นักกีฬาและตำแหน่งตัวจริง/สำรอง
- `matches`, `athletics_events`, `athletics_results`, `medals`
- `team_files` และไฟล์ทีม CSV/Excel ที่ยืนยันตำแหน่งได้
- ไฟล์ประวัติผู้ฝึกสอนทุกเวอร์ชันใน `school-coaches`
- เฉพาะ `management.teams` / `management.fixtures` ในกติกาแข่งขัน พร้อมเพิ่ม revision

ข้อมูลที่เก็บ: `schools`, `profiles`, Supabase Auth, คำขอสมัคร, ประวัติ/โลโก้โรงเรียน, รายการกีฬา/UUID, โควตาและกติกา, คะแนนชนะ/เสมอ/แพ้ และข้อมูลสำรองเดิม

ขั้นตอน:

1. กด **ตรวจข้อมูลก่อนเริ่มการแข่งขันใหม่** ตรวจจำนวนรายการที่จะล้าง
2. พิมพ์ **ล้างข้อมูลการแข่งขันทั้งหมด** แล้วกดยืนยัน ระบบตรวจว่าข้อมูลยังตรงกับตัวอย่างล่าสุด
3. ระบบเปิดโหมดบำรุงรักษาและทำสำรองแบบส่วนย่อยใน private Storage ก่อนลบรายการแรก ระหว่างนี้ API สมัครนักกีฬา จัดสาย บันทึกผลและผู้ฝึกสอนจะปฏิเสธการเขียน
4. รอความคืบหน้า หากปิดหน้า/เครือข่ายสะดุด ให้ตรวจสถานะแล้วกด **ดำเนินการล้างข้อมูลต่อ** ข้อมูลที่ลบแล้วไม่ถูกลบซ้ำ
5. เมื่อเสร็จ กด **ดาวน์โหลดข้อมูลสำรอง** เก็บไฟล์ในพื้นที่ส่วนตัว มี **ดูข้อมูลสำรองย้อนหลัง** สำหรับดาวน์โหลดหลังเปิดหน้าใหม่

หากต้องยุติงาน ใช้ **ยุติงานและเปิดให้บันทึกข้อมูล** ข้อมูลอาจถูกล้างบางส่วนแล้ว สำรองยังอยู่ ต้องตรวจข้อมูลคงเหลือก่อนเริ่มใหม่ งานที่ยุติจะไม่กลับมาลบต่อ หากมีคำขอเดิมค้าง ระบบให้รอ 5 นาทีเพื่อไม่ให้สองคำขอลบ/ปลดล็อกพร้อมกัน

หากล้างครบแต่การปลดโหมดบำรุงรักษาสะดุด จะมีปุ่ม **ปลดโหมดบำรุงรักษาหลังล้างข้อมูล** ส่วนงานที่ยุติแล้วแต่ยังปลดล็อกไม่สำเร็จมีปุ่ม **เปิดให้บันทึกข้อมูลอีกครั้ง**

## สำรองและขอบเขตทางเทคนิค

- สำรอง private JSON ส่วนละไม่เกิน 1 MB มี manifest และ SHA-256 ไฟล์ดาวน์โหลดประกอบส่วนย่อยและตรวจ hash ก่อนส่งออก รองรับชื่อภาษาไทย
- สำรองประกอบด้วยแถวข้อมูลและเนื้อหาไฟล์ที่กำลังล้าง ไม่รวมรหัสผ่านหรือ Auth sessions ไม่มี public URL ของไฟล์สำรอง
- จำกัด snapshot 6 MB และตรวจขนาดเงื่อนไขแต่ละแถวก่อนเริ่มงาน หากข้อมูลหรือโครงสายใหญ่เกินขอบเขตที่ล้างผ่าน REST ได้อย่างปลอดภัย ระบบปฏิเสธก่อนลบ ให้สำรอง/จัดการผ่านผู้ดูแลฐานข้อมูล
- Route กำหนด `maxDuration = 60` และใช้ lease กู้คำขอหลัง 5 นาที การนำไปรันบน hosting อื่นต้องรักษาข้อจำกัด runtime ให้สั้นกว่า lease นี้
- เป็น REST หลายคำขอ ไม่ใช่ transaction เดียว ข้อมูลที่เปลี่ยนจากสำรองหรือมีเพิ่มจะทำให้งานหยุดเพื่อรักษาข้อมูลใหม่ ไม่มีการลบทั้งตารางแบบไม่ตรวจเป้าหมาย
- ระหว่างล้างไม่ควรเขียนตารางหรือไฟล์ตรงจาก SQL Editor, service key หรือเครื่องมือภายนอก เพราะการเปลี่ยน Storage และ FK จากนอก API ไม่สามารถรวมเป็น transaction กับงานนี้ได้
- ในการพัฒนาครั้งนี้ทดสอบ reset และการตั้งรหัสผ่านด้วย SDK HTTP fixtures และ E2E เท่านั้น ไม่ได้ล้างการแข่งขัน เปลี่ยนรหัสผ่าน หรือลบโรงเรียนจริง

ผลตรวจ: unit/SQL/API 146 กรณี และ E2E 36 กรณีผ่าน รวมมือถือและดาวน์โหลดสำรองภาษาไทย มีการตรวจโค้ดอิสระและ regression สำหรับการล้าง/ยุติงานพร้อมกัน
